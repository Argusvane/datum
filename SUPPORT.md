# Getting help with Datum

Datum is pre-release and maintained on a best-effort basis. Pick the route that fits what you have.

| You have | Go to |
|---|---|
| A question about how to use Datum, an idea, or something to show | [GitHub Discussions](https://github.com/argusvane/datum/discussions) |
| A bug, or a missing piece you can describe | [GitHub Issues](https://github.com/argusvane/datum/issues). Use the bug or feature template and say which component, host and version you ran |
| A vulnerability | Privately, as [SECURITY.md](SECURITY.md) describes. Never in a public issue or discussion |
| A conduct concern | [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) says where to write |
| A change you want to make | [CONTRIBUTING.md](CONTRIBUTING.md) |
| Commercial support, services or a conversation about a deployment | Argusvane, at contact@argusvane.com |

## Before you ask

- The documentation is at https://datum.argusvane.com/docs/. It is the canonical guide; search it first.
- The release status, what is published and what is not, is in
  [Release status](https://datum.argusvane.com/docs/introduction#release-status).
- Search the existing discussions and issues for your question.

A good question names the Datum version or commit, the host (browser only, Spring Boot, FastAPI or your own), the
runtime versions, and the smallest form definition or request that shows the problem.

## What to expect

The project is maintained by Argusvane, and nobody is on call for it. Questions and issues are answered when the
maintainers can, with no promised response time. Security reports have their own timetable in
[SECURITY.md](SECURITY.md). Commercial support is arranged with Argusvane directly and is separate from these
public channels.

## Roadmap

There is no separate roadmap document. What is planned is the rows marked Planned in the table of server hosts in
[Server hosts](https://datum.argusvane.com/docs/server-hosts) (`site/docs/server-hosts.md`). Anything else is
discussed in GitHub Discussions before it is built.
