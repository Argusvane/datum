# Sandbox ABI

`WASM_ABI_VERSION` (`engine/form-engine/validation/wasm/wasm-validation-host.ts`) is the version of the contract between a host and the validation sandbox program: the serialized run context going in, the outcome and the `__datum_inspect` requests and answers coming out. The current value is `1.0.0`. The major number changes when the shape of a payload breaks, or when a definition the kernel accepted is refused; the minor number changes when the program judges something differently or adds an optional key.

Where it is read:

- The sandbox program's banner names the version it was built for, and `kernelInspectAbi()` answers the same string; a test pins the two to the constant.
- A `__datum_inspect` request carries an `abi`. The program answers a request of its own major that is no newer than its own version, and refuses any other (another major, a newer version, a malformed or missing one) as `abi_mismatch`. A host that binds a program probes it this way and refuses a program that does not answer for the version the host needs.
- `<datum-form wasm>` refuses a loaded `datum-wasm.js` whose exported `WASM_ABI_VERSION` is not the element's own, and `WasmValidationHost` refuses an instance whose `abiVersion` is not its ABI's.
- The conformance suite (`docs/conformance-suite.md`) holds a program to this version's golden file and checks it against its manifest.

A host builds the program from the source of the release it runs, and deploys it to servers first, or together with the browser bundle, so a server is never more lenient than the browser it sits behind. The program speaks one contract and carries no compatibility shims: a host whose program is below the version it expects refuses it at start instead of judging by other rules.

The PDF program has its own contract and version, `PDF_ABI_VERSION`: [PDF ABI](pdf-abi.md).

## The run context

| Key | What it carries | ADR |

The page's own host context is a separate thing from the server's. `<datum-form>` takes a `hostContext` property and a `host-context` attribute, copies the value as plain JSON (`plainHostContext`, `core/state/host-context.ts`: a function, symbol, bigint, non-finite number or non-plain object is left out with its path, as is anything past 64 levels or 10,000 values, and the element reports `host-context.invalid`), and a value that is no object clears the context. The runtime takes it as `FormRuntimeDependencies.hostContext`, and a later change goes to `FormRuntime.setHostContext`, which recomputes in place: typed answers stay and nothing is announced as a new form. What reads the context reads it through a getter on every use, the journey's presentation overlay included, so the overlay sees the replacement too. These values are for display and the browser's own judgement: they never enter the submission envelope, because a server that took them from the browser would judge by whatever a client chose to send. The in-page sandbox (`<datum-form wasm>`) is handed the page's context with the day, since it stands in for the browser's judgement. `@argusvane/datum-submissions` is the reference for a server: `receive(input, { hostContext })` and `validate(input, { hostContext })` copy the value through JSON and pass it to the sandbox, and the record's PDF is drawn with the same context.

## The outcome

`errors` (error codes with their parameters) and, for a run that does not block, the sanitized `values`. An error is identified by its code, component, path, stage, source, severity and parameters, never by message text: the outcome carries no prose and no presentation, and the renderer words each code from the host's `ValidationMessageCatalog`. The optional keys, each present only when it has something to say:

- `logs`;
- `clientDerived`: the value paths of answers worked out in the browser and kept as sent (a worked-out value's target, a calculation the kernel could not reproduce, any calculation reading one of those); each was held to the form's rules like any answer;
- `pageComponentIds`: the components in scope for `page`, by the kernel's own placement, so a host that cannot run the engine keeps a page's check to the page;
- `clockDependent`: components and pages whose rules read the clock;
- `serverRules`: components whose `server` or `server-secret` rules the run applied;
- `visibilitySkipped`: components whose `visibleWhen` the server could not replay, treated as hidden for requiredness (one reading `host.` with no `hostContext`, one scoped to the browser, one reading the clock with no `today`);
- with `reportFold`: `withheld`, `effectiveState`, `submittable` and `trace`;
- `index`: whenever the outcome carries `values`, the host's one-row-per-answer index of them, `{ path, delta, value }`, the path without its entry indexes and a list of scalars one row per item, built from the outcome's own sanitized values so no host rebuilds it with its own reading of the schema;
- with `document`: `canonical` (key order by UTF-16 code unit, no whitespace) and `digest` (lowercase SHA-256 hex of its UTF-8 bytes), whatever the verdict. The hash is computed before the compile, the fold and the validators, and validators never see `document`, so nothing in the run changes it. The engine's own canonical serializer sorts the same way, so the browser and every host name one record by one digest, and `@argusvane/datum-submissions` finds a record, for `check` and for PDF attachment verification, by that digest alone.

Object keys sort by UTF-16 code unit everywhere, not by `localeCompare`: ICU collation differs between engines, and the ABI requires byte-identical serialization from QuickJS and V8. The program serializes its own outcome (`kernelStableStringify`), so the output is ABI-canonical whichever host ran it.

After every sandbox run, successful or fail-closed, `FormRuntime` publishes `WASM_VALIDATION_COMPLETED` with the exchange: the request values, the effective `unknownFields` mode, the injected external data, the outcome or the execution error, whether the run blocked, and its wall-clock duration (the schema is left out, since the host holds it). A sandbox that cannot run, or a host failure, becomes one blocking `wasm.execution_error` instead of a rejected promise. `submit()` uses the sanitized values the outcome returns for everything after the stage, and writes the wasm and server stage errors to the `ErrorStore` with `ERRORS_CHANGED` published.

## What the kernel judges

The kernel is one set of import-free functions, `engine/form-engine/validation/wasm/portable-kernel.ts` and the modules whose functions are spliced beside it. The in-process reference adapter calls them directly and the QuickJS adapter splices their `Function.prototype.toString()` output into one program, binding the entry points by `fn.name` so a minifier's renames survive. The splice list is built while the kernel module loads, so a module the kernel imports cannot import the kernel back. The kernel re-implements the data-scope and field-constraint readings it must not import, and `engine/tests/portable-kernel.test.ts` holds the two readings identical; the package's parity tests require byte-identical outcomes between QuickJS and V8 for every vector. A form that uses only standard constraints needs no wasm plugin: the kernel runs the constraint stage itself (`stage: "field-constraints"`, `source: "wasm"`).

The kernel, the path engine, the fold and the form tests' server driver, parser and judge (`FORM_TEST_PARSE_FUNCTIONS` and `FORM_TEST_RUN_FUNCTIONS`, listed beside the kernel's own functions in `PORTABLE_KERNEL_FUNCTIONS`) are spliced from their own modules. Under Vite's SSR transform (vitest, and the vite-node script `packages/datum/scripts/write-sandbox-program.ts` that writes `datum-sandbox-program.js`), a call from one module to another is written against an import namespace (`__vite_ssr_import_3__.journeyPath(…)`), so `buildSandboxProgram` (`packages/quickjs-wasm-host/src/sandbox-program.ts`) declares each namespace it finds in the spliced source as one object holding every spliced function by name. A production bundle has no such names, so nothing is added there. `engine/tests/journey-path.test.ts` ("the path engine's own list") holds the path engine's list to calling nothing outside it.

- Data keys: a field's `configuration.dataKey` places its answer, and a repeating section's entries sit at its collection path as written ([0109](../adr/0109-data-keys.md)).
- Visibility, enabled and read-only state, requiredness, calculations, a journey's path and the hidden-value policies are decided by the shared fold before anything is judged, the browser's way: rules over the submittable view, hidden components by their hidden-behaviour policy, excluded answers dropped ([0178](../adr/0178-the-fold-and-server-parity.md)). A field a journey places on no page is judged as the whole form judges it, and a presentation's nodes place the form fields they reference ([0121](../adr/0121-journey-only-fields.md)).
- `rules.requiredWhen` (required or the rule) and `rules.validWhen` (`rule`), both in [0120](../adr/0120-rules-that-add-checks.md).
- A rule or calculation reading `host.` is judged only with `hostContext`. A journey route's `when` never reads `host.`, and a field a journey places on no page whose visibility reads `host.` keeps the lenient fold with or without a context ([0142](../adr/0142-the-validation-gate-fails-closed.md)).
- Caps and formula rules are below; the formula language is in [formulas](../formulas.md).

### Which keys are known

- A key is known only by shape. Its entry indexes must be canonical (`[0]`, `[1-9][0-9]*`) and sit right after a repeating section's collection path, once. Any other bracketed key is unknown, and `unknownFields` decides it: `province[0]` beside `province`, `items.sku` with no index and `items[0][1].sku` do not pass. A section whose collection path is written with brackets has no known keys at all. A node that holds no data (a button, static HTML, an image, a signature, a plain group) has no known key.
- Nested posts are flattened first. Rows posted whole at a collection path, and an object posted at a data-scoping container's key (`addr: { pick }`), are read a level at a time as the flat keys the runtime stores (`addr.pick`, `items[0].addr.pick`), before the fold, so the allowlist, the option check and the constraints see one shape. A key sent flat beside the nested spelling wins and the nested one is logged as superseded. A scalar, a list or null at a container's own key, a non-list at a collection path, and anything nested past 16 levels are not stored: an unknown key (dropped under `strip` and `keep`, `unknown_field` under `reject`).

### Answers

The codes below (`text`, `file`, `fileCount`, `fileSize`, `number.min`, `number.max`, `date.min`, `date.max` and `option.sourceUnavailable`) are in `ENGINE_VALIDATION_CODES` and have English wording in `DEFAULT_VALIDATION_MESSAGES` (`core/localization/validation-messages.ts`), so a binding or a translation can word each of them.

- Kinds ([0142](../adr/0142-the-validation-gate-fails-closed.md), [0122](../adr/0122-number-and-date-answers-are-checked.md)): a `text` or `textarea` answer is a string (code `text`); a number, boolean, list (an empty one too) or object is refused, and `required` is not satisfiable by `{}`, `0` or `[""]`; a plugin type is nobody's to check. A `number` is a finite number or a plain decimal numeral (`number`); a `date` is a real `YYYY-MM-DD` (`date`). The code is the kind (`kernelAnswerKindCode`), and the browser stage refuses the same answers.
- Bounds: `configuration.min` and `max` on a number or date field are inclusive (`number.min`, `number.max`, `date.min`, `date.max`, with `parameters.min` or `parameters.max`). A bound is a finite number (or a plain numeral as text) or a real `YYYY-MM-DD`; anything else is no bound, and an inverted pair drops both. A numeral too large for a double reads as infinite on both engines. The order of the checks is required, kind, bounds, then length and pattern.
- Attachments: a file answer, or each item of a list, is an object with a non-empty string `storage`, a string `name`, a string `type` and a finite number `size` (`file`; the base64 `data` is not inspected). A count over the field's allowance is `fileCount` (`parameters.count`, `parameters.maxFiles`): one for a field that is not `multiple`, else `configuration.maxFiles` (a whole number of 1 or more), else 100. A declared `size` that is negative or not an integer is `fileSize` (the kernel only; zero is valid). The builder offers no `maxFiles` box; the definition carries it.
- Hidden answers: format codes (kind, length, pattern, file shape and size) hold for a hidden answer that is still submitted; bounds and file counts do not, because the browser's hidden-value policy drops those answers.
- Row fields: a field in a repeating section is checked at each entry's key (`items[0].sku`) and the error's `path` names it. `required` errors only for entries that lack the field; no entries, no error; the bare path is not read. `requiredWhen` inside a section stays unread; only the tick is per entry.
- Row calculations: `rules.value` on a row field is evaluated for each entry, with `row.` reading that entry, `rowIndex()` the 1-based place and `rowCount()` the count. A forged `items[0].total` is replaced, and the run log says the calculation was recomputed. An entry whose inputs are missing, or that reads `host.` or runs in the browser, is kept as sent and listed in `clientDerived` by its entry key. An aggregate over the whole section names no answer and is kept as sent.
- Unanswered inputs: a calculation is kept as sent only when an unanswered read may have been withheld (`kernelReadMayBeWithheld`): the read names no data-holding component of the form, or sits in a repeating section, or the component can be hidden and its own `hiddenValueBehavior` is anything but `retain` (by default a hidden answer is left out of the submission). With a journey, a read is also a maybe until the fold has placed the components; after that a component only on pages the path skips is withheld for certain, and its read is the empty operand. Any other unanswered read is worked out over the empty answer: a forged sent value is replaced and what reads it follows.
- A visibility the server cannot replay (an own or inherited `visibleWhen` that reads `host.` with no host context, runs `browser`, or reads the clock with no day) sets `required` false for the node, the tick and `requiredWhen` alike (`kernelFoldRelaxUnreplayable`), unless the node says `hiddenRequiredBehavior: "required"`. The node stays visible for validation and its hidden-value policy is untouched; the outcome lists it in `visibilitySkipped` (also on `SubmissionRecord` and the service verdict).

### Repeating sections and data grids

A data grid is a collection-bound container whose children are the row template, so a column's cell is a field of a repeating section with the same codes and paths. A row posted as `{}` is a row, and so is a posted row none of whose keys is stored. The row count is held to `configuration.minRows` and `maxRows` (`rows.min`, `rows.max`), or to `rules.minRows` and `rules.maxRows` when those evaluate to a whole number from 0 (past 500 read as 500), form-scoped over the settled view; an unconfigured grid is held to 500 rows ([0153](../adr/0153-a-data-grid-container.md)). `kernelNormalizeDataGrids` binds a grid with no `collection` at its id at the top of every run, `check`, `inspect` and `public`, before anything walks the tree.

### Choice answers

`portable-options.ts`. After the fold, the kernel holds every choice answer the run retains, on a hidden component too, to its options, and answers `option.notAllowed` (stage `options`, `parameters.keys`). The check runs on every host, so inline options and answer shape are enforced in the browser's in-process run as well ([0037](../adr/0037-inline-options-and-wiring-time-data-sources.md) holds the options).

- Shapes: a select or radio answer is a string; checkboxes are an object of booleans, only the `true` keys picking. A plugin type's answer must have a choice's shape (a text, a finite number, a boolean, a list of those or a record of booleans); any other shape is refused whole.
- Keys are matched index-free, and rows posted whole at a collection path are checked row by row. A choice in a row is reported as a section's field is: one error per question, the index-free path, every refused key in `parameters.keys`.
- Inline options come from the definition. A source's options come from `optionSnapshot` (`sourceId` to `{ value, label? }[]`, the PDF ABI's shape). A source the snapshot lacks (none sent, not a record, the id missing, or an entry that is not a list) refuses an answer that picks a value as `option.sourceUnavailable` (stage `options`, `parameters.keys`, `parameters.sourceId`), with one `warn` log line; an answer that picks nothing, and an unanswered question, pass. A source's snapshot list that is empty allows nothing (`option.notAllowed`).
- `data.answersFree: true` (the boolean only) beside `data.sourceId` is the author's opt-out for a source that only suggests: the snapshot is not consulted for that choice on either side (the browser does not load the source for the snapshot), the answer still has its kind's shape and the field's limits, and `inspect` lists the source on the component's path as `source: { id, free: true }`. The builder offers it as a switch in the Data section.
- A choice with no usable options and no source is not a choice and is not checked.
- Components sharing a data key: refused only when no choice there accepts the answer, and the check is skipped only when the other component is a plain `text` or `textarea` (the "Other, please specify" pattern).

### Validators and formulas

- A plugin validator answers `{ errors }`. One that throws blocks the run with `validator.failed` (stage `validation`, `parameters.validator`), and the outcome, digest included, still comes back; a heap exhaustion is such a throw. One that returns no usable answer (`undefined`, `null`, a non-object, a promise, an object with no `errors` list, or an entry that is not a record with a string `code`) makes the run throw: the service answers `validator_unavailable` (503, nothing kept, no hook run), the browser the blocking `wasm.execution_error`. A returned answer is copied once and the copy judged, so a getter that answers differently on a second read changes nothing.
- A returned error whose `severity` is present and not `error`, `warning` or `info` is copied with `severity: "error"`; the service's `blocks()` and the runtime's `isBlocking` read the same way.
- A validator reads a deep-frozen copy of `context.values` (`kernelFrozenCopy`; an own `__proto__` stays a key). A write from sloppy code is ignored; from strict code (every ES module and the sandbox program's own text) it throws and becomes `validator.failed`. The stored values are built from the pristine object.
- Formulas are FEEL text compiled once per definition into a copy; `formulaErrors` and `riskyPatterns` decide what a problem does ([0139](../adr/0139-formulas-rules-as-feel-text.md), [0142](../adr/0142-the-validation-gate-fails-closed.md), [formulas](../formulas.md)). The kernel wraps the plugin functions it evaluates and records `{ where, name, message }` once per rule and function. Under `formulaErrors: "fail"` each record is a blocking `formula.invalid` (stage `definition`, `parameters.where`, `.message`, `.function`) and the plugin validators are skipped; under `warn` it is a `warn` log line (`formula function threw: ...`). The browser wraps its functions the same way and adds the same error to a whole-form or journey page run under `fail`, naming the rule more coarsely (`rules:<id>` for the three state rules, no key). A rule that calls an unknown function and runs on the server (`run` is `both`, `server` or `server-secret`; the key can take a server scope) is refused as `formula.invalid` (`parameters.function`) under `warn` as well as `fail`; a rule scoped `run: "browser"`, a browser-only key, a journey condition and a PDF site keep the policy. The submissions service compiles once at register, so its `judge` adds the same error from the form's recorded problems. A `server-secret` rule's problems, log lines and function warnings carry `where`, the code and the sentence "The details of this problem are withheld.", never the rule's text or the unknown function's name.
- Calculations that never settle are `formula.invalid` (stage `definition`, `parameters.message` "the calculations do not settle: a -> b -> a") under every policy word, with no validator run.

### Journeys and the settled view

With a journey, an answer the fold withheld, and a component on a page the path skips, are no input to a calculation. Where a calculation reads one, the kernel works the calculations out again over the answers less the withheld ones, with skipped components counted as known-empty, and folds again, until the withheld answers and the skipped pages stop changing (at most five rounds; a view that comes back to one already tried, or one that does not settle, is `fold.unsettled`). The browser runs the same loop. A forged off-path answer therefore derives nothing and steers no later page. A journey with duplicate page ids is refused everywhere (`journey.invalid`; a submission naming it is `journey.unknown`).

### Limits at run

- Components nest at most 32 levels, the root counting as level 1 (a component at level 33 is refused); the form's tree and each object entry of a journey page are measured apart, by an iterative pass before anything walks the tree, because the wasi build of QuickJS traps at about 80 levels of recursion. A run answers `definition.tooDeep` (stage `definition`, `parameters.where`, `limit`) and an inspect request answers `{ ok: false, error: { code: "definition.tooDeep" } }`. The browser's `compileFormDefinition` refuses a form tree past 32 levels with a message.
- A journey over 1,000 pages is `journey.page.tooMany`, a page with more than 64 routes `journey.route.tooMany`. A journey condition that reads the clock with no `context.today` is `journey.clockDependent`; a host that runs a journey passes `today`.
- A run reports at most 10,000 errors; past it the list ends with one `errors.truncated` entry (`parameters: { reported, shown }`), and the verdict is taken before the cut; when only warnings were cut, the marker has severity `warning`.
- Every whole-text formula function except `len` and `empty`, which read the whole text, works on the first 10,000 characters of a longer text and says so with one `text.truncated` warning. The list cap counts the tree a result expands to, each copy of a shared list again. Each run-log entry is capped ([0050](../adr/0050-sandbox-run-log.md)).
- Row-level work is linear in the number of entries, and the time budget counts the paths the rules read, not a grid's rows times columns: a host that validates very large grids sets `maxEvalMs` itself.

### Regular expressions

`kernelRegexRisky` reads a parsed pattern (groups, branches, quantifiers, classes, by code point) and flags the shapes that backtrack catastrophically; a pattern it cannot follow but the engine accepts is risky (fail closed). The analysis has a step budget, so any pattern of at most 2,000 characters is read in bounded time; a field `pattern` over 2,000 characters is risky at run time and refused at Save (`component.pattern.tooLong`). The verdict on a field pattern is kept on the prepared definition and the one on a `matches` pattern on the run's regex cache. A pattern built at run time is refused at the call unless `riskyPatterns` is `allow`. The pattern-writing guide is in [formulas](../formulas.md).

## `__datum_inspect`

The program has a second entry point beside `__datum_run`, for what a host must know about a definition before it serves or stores it, so a host that cannot run engine TypeScript ports nothing. `__datum_inspect(requestJson)` answers canonical JSON and is pure: the same request answers the same bytes on every host. A request is `{ abi, op, definition, formulaErrors? }` with one of four ops ([0139](../adr/0139-formulas-rules-as-feel-text.md), [0154](../adr/0154-form-tests-scenarios-over-rules-journeys-and-verdicts.md)). An `abi` of another major or a higher minor than the program's is `abi_mismatch`, a request of no usable shape `invalid_request`; neither throws. When the host set no budget, an inspect request gets 250 ms plus 1 ms per kilobyte of the request, at most 5,000 ms.

- `public`: the definition to serve a browser, without the rules the compile honours as `server-secret` and without a secret rule written where no server scope is allowed. The removal covers the form, the journeys and the PDF layouts alike, including a children slot that is not a list. The definition's `tests` are not served.
- `check`: `{ problems, warnings, policy, verdict }` from the formula compile, and the definition's structure (`structure`, `structureWarnings`, `limits`), which lets a host refuse a definition at save or registration time instead of per submission (`core/expressions/definition-structure.ts`).
  - The request may carry `types`, the component types the host can draw (at most 4,096 names of at most 128 characters, else `invalid_request`); absent, no type is judged unknown (`component.type.unknown`).
  - Each problem is `{ code, where, message?, limit? }`. `where` is `root > slot > id` (an id the grammar does not allow shows as `#<position>`), `journey:<id>:page:<id>:route:<n>`, `pdf:<id>` or `definition.<key>`, at most 80 characters, cut from the left. `message` is a fixed sentence built from the code and the limit, never from author text. Each list holds at most 200 problems and ends with `definition.problemsTruncated`. A problem at a `journey:` or `pdf:` site is redacted when a server-secret value is present in the definition.
  - The verdict is `fail` when `structure` is not empty, under every formula policy.
  - `limits` answers the caps. A definition past one is answered with the size problems alone, without compiling its formulas, and the code is the matching `*.tooMany` one: 10,000 components, 2,000 inline options on one component and 50,000 in all, 64 locales, 32 journeys, 1,000 pages, 64 routes on a page, 64 PDF layouts, and 65,536 characters of collection paths together (`definition.paths.tooLong`).
  - The structure check refuses reserved ids (`component.id.reserved`, `journey.id.reserved`, `journey.page.id.reserved`, `pdf.layout.id.reserved`), a journey page that carries a `when` (`journey.page.when`), a field `pattern` that does not compile or is over 2,000 characters (`component.pattern.invalid`, `component.pattern.tooLong`), chrome parts without an id or with a repeated one (`chrome.part.id.missing`, `chrome.part.id.duplicate`), a malformed `kinds` map (`kinds.invalid`, `kinds.tooMany`, `kinds.type.invalid`, `kinds.type.engine`, `kinds.base.invalid`), and a `localization` block that is not an object, whose `supportedLocales` is not a list of `{ code, label? }` entries with a code of the locale grammar, or whose `defaultLocale` is not such a code (`localization.invalid`).
  - `structureWarnings` lists what the form tolerates: unknown keys and types, `component.limits.inverted` (a minimum above its maximum, so the form ignores both), duplicate option values, `definition.components.large` over 2,500 components and `option.count.large` over 500 options on one component.
  - The compile reports a condition that is provably no yes-or-no as the warning `condition.notBoolean` among `warnings`, never `problems`, so `formulaErrors` does not act on it.
- `inspect`: a static inventory of the rules (`run`, reads, `host.` and clock reads, functions), `functionsUsed`, `pluginsNeeded`, and `paths`: each value path the kernel reads, in document order, as `{ path, componentId, type, holdsData, collection?, source? }`, covering data keys, scoping containers, collections (a data grid is a collection) and a choice's source. It lists function names even for a secret rule, because `pluginsNeeded` is how a host knows which rule modules to register. `check` parses strictly with the host's function signatures, while `inspect` parses leniently, so a function no plugin provides is still listed. `run` is always `browser` for the three browser-only rule keys.
- `test`: the form's own tests, run on the kernel's reading. The request is `{ abi, op: "test", definition, tests?, formulaErrors? }`; `tests` is sidecar text, absent or `null` meaning the definition's own `tests.scenarios`. The answer is `{ ok: true, op: "test", report: { scenarios, summary, problems } }` in the runner's shapes (`FormTestOpReport`). The kernel walks each scenario as the engine's runner does over the kernel driver, so the engine's suite can hold the sandbox to the in-process bytes. A rule the server does not apply is skipped (`unreplayable.*`), and there is no clock, so a form that reads the day needs `given today` in each scenario. The op runs the host's plugin functions and validators as a run does. A scenario's `given host.` values are every run's `hostContext` (a dotted name nests), so its `host.` rules are judged as the browser judges them; a scenario with none runs with no `hostContext`, and an expectation that a `host.` rule decides skips as `unreplayable.host`. The `change <field>` line follows a Check answers row's Change link as the browser does, and is refused (`action.refused`, reason `change.notReview`, `change.off`, `change.notListed` or `change.unreachable`) where the browser has no such link.
  - Caps, refused as `invalid_request` with `where` and `limit`: `tests` that is not text, more than 256 KiB of test text, more than 200 scenarios, a scenario of more than 1,000 statements, a definition past a size cap. The op runs every scenario, so the size of its request says nothing about its cost; the QuickJS adapter gives it the cap of the inspect budget.

## The program and its limits

An adapter whose instantiation is asynchronous (real module loading) is wired with `WasmValidationHost.create(input, { adapter })`, which returns a promise of the host; the constructor throws `use WasmValidationHost.create()` for an adapter whose `instantiate(plugins, abi)` returns a promise, and is for synchronous adapters and a ready instance. `run()` is asynchronous either way. An instance may have a `dispose()`, which the host calls when it is released.

The program is one closure. `buildSandboxProgram` wraps the kernel's functions, the prepared-definition cache, the plugin registries (appended to only by `__datum_register`, sealed at the first run or inspect), the budget state and a local alias of every language global the kernel reads (`INTRINSIC_ALIASES`) in one function, so they are locals no plugin can name. The only globals are `__datum_register`, `__datum_run` and `__datum_inspect` (non-configurable). A host takes hold of those three once, right after the program loads and before the freeze and any plugin module (`QuickJsProgramHost.captureEntries`; the worker does the same), and calls those handles. A module's top-level code can call `__datum_register` itself, append-only and before the first run; it cannot read, empty or reorder what is registered. A host may set `globalThis.__datum_cache_chars` before the program to bound the prepared-definition cache; the program reads it once and removes it, and a host whose sandboxes serve one call each sets it to 0.

The language is frozen before any plugin loads. `FREEZE_INTRINSICS_SNIPPET` (exported from `sandbox-program.ts`, a string) is evaluated once after the program and before the plugin modules. It freezes every object reachable from the global object's values: each intrinsic, every prototype, every function among their properties and accessors, recursively, and the three entry points. Every data property of the global object becomes non-writable and non-configurable, and the snippet makes that hold on Bellard's QuickJS as on quickjs-ng: before it freezes anything it replaces `Object.defineProperty`, `Object.defineProperties` and `Reflect.defineProperty` with versions that, on the global object, read the key and the descriptor once and refuse a change the language refuses for a non-configurable property (a `TypeError`, or `false` from `Reflect.defineProperty`), and `new Proxy` and `Proxy.revocable` refuse the global object as their target. On any other object the three functions are the originals. The global object's prototype, where a bare name that is not one of its own properties is looked up, keeps the one it starts with: `Object.setPrototypeOf` (a `TypeError`), `Reflect.setPrototypeOf` (`false`) and the `__proto__` setter on `Object.prototype` (a `TypeError`) refuse a different prototype for the global object and are the originals for every other object. The global object stays extensible, so a plugin may define globals of its own. On the frozen prototypes `constructor`, `toString`, `valueOf`, `toLocaleString`, `toJSON` and the `name` and `message` of the error prototypes are accessors: reading gives the original value, assigning to an instance defines an own property (so `class MyError extends Error` setting `this.name` works), and assigning to the built-in prototype itself throws a `TypeError`. `QuickJsWasmHostAdapter` takes `freezeIntrinsics` (default true); `false` is the documented opt-out for a plugin that must patch a built-in. `dist/datum-sandbox-program.js` (the text `datum-wasm.js` evaluates, as a plain script any QuickJS context can evaluate) does not contain the snippet. A host that embeds the program itself therefore evaluates the program once, captures the three entry points into locals, evaluates the snippet, registers the same plugin modules, and then calls `__datum_run(contextJson)` per submission with the schema root, the values, the locale and the external data of its own.

Plugin modules. A plugin contributes at most one `wasmPlugin` (`{ id, version, source }` on `FormPlugin`; `"wasmPlugin"` is a manifest contribution kind): an ES2020 program whose completion value is a module object `{ validators?: Array<(context) => { errors }>, functions?: { name: fn } }`. `functions` registers formula functions ([formulas](../formulas.md)); unknown module keys are ignored, so a contribution kind can be added without an ABI break. `PluginPlatform` collects the modules into `PluginPlatformResult.mergedWasmPlugins`, and the host hands them to `createQuickJsValidationHost(mergedWasmPlugins)` once at startup; every installed plugin's module is wired for every form. `toSourceModule` and `toSourcePlugin` turn closure-free hosted functions into portable source (a convenience; a production plugin writes explicit `source`), and `certifyWasmPlugin` proves that a module evaluates in QuickJS, yields function validators and survives a probe run.

Trust. Plugins are trusted first-party code: the sandbox is a determinism and parity boundary, not a defence against malicious validators, and it has no bundle signing (the manifest's `signature` field is carried through as given and nothing checks it). QuickJS gives no ambient authority by construction (no fetch, filesystem, process or timers), and the program disables `Math.random` and `Date`. `WasmSandboxPolicy` is typed with `allowNetwork`, `allowFilesystem`, `allowProcess` and `allowEnvironment` all `false`, `WasmValidationHost` throws on any other policy before a run, and `WasmValidationHost.STRICT_POLICY` is what the runtime passes. The `security:wasm-sandbox-isolation` release gate checks that guarantee; the conformance suite attacks the rest.

The limits below are safety nets against runaway code.

| Limit | Value |
| --- | --- |
| Time | The interrupt deadline is wall-clock. A host-set `maxEvalMs` is used exactly as given. Left unset, it scales with the definition: 250 ms, plus 5 ms per rule read, plus 1 ms per kilobyte of definition text, capped at 5,000 ms and worked out once per definition (remembered under a hash of the definition), then 2 ms per kilobyte of the serialized context on every call (`SCALED_MS_PER_REQUEST_KB`), capped at 5,000 ms again. A form of a few rules keeps 250 ms. |
| Startup | `maxStartupMs`, 2,000 ms by default (`DEFAULT_STARTUP_MS`): evaluating the program and registering the plugin modules. |
| Memory and stack | 32 MiB and 1 MiB (`VALIDATION_PROFILE`). |
| Request | At most 320 levels deep and 32 MiB of text; a larger request is refused before QuickJS sees it (`request_refused`). |
| Outcome size | `QuickJsProgramLimits.maxResultLength`: 8 MiB of UTF-16 code units in the validation profile. A longer answer to a call is refused as `outcome_too_large` (message `outcome.tooLarge`) and nothing of it is kept; the submissions service answers it as a typed 422, since a filler can cause it with `unknownFields: "reject"`. An `inspect` answer is not capped by it. |

A host's classifier blames the definition (422 `definition.tooCostly`) only when the guest itself reported an interrupt or an out-of-memory; a wall-clock limit, the output limit or an unavailable runtime stays a 503. A host may remember a `definition.tooCostly` verdict for a short time per definition, so repeated Saves do not each burn the time budget (the Spring Boot host's `datum.forms.too-costly-memory`).

A server gives every call a fresh sandbox; [Sandbox and server runs](server-runs.md) describes the Node worker host and the settings of each runner.

## Version ranges

A plugin's `engineRange` and a plugin dependency's `versionRange` use a small explicit grammar, a subset of npm semver implemented in `registry/version-range.ts` with no third-party dependency. A range is one of:

- an exact version (`1.2.3`); a bare version, with or without missing segments, matches only itself, and a missing segment reads as `0`;
- caret (`^1.2.3`): at least that version, below the next major; for a `0.x` version below the next minor, and for `0.0.x` below the next patch;
- tilde (`~1.2.3` and `~1.2`): at least that version, below the next minor; `~1` below the next major;
- a comparator, `>=`, `>`, `<=` or `<`, with one version;
- a wildcard: `1.x`, `1.2.x` (`*` in place of `x` is the same), or `*` or `x` alone for any version.

Versions are `major.minor.patch` numeric tuples; pre-release and build metadata are not supported. `parseVersionRange` and `satisfies` are built on `normalizeVersion` and `compareVersions` (`registry/versioning.ts`). `ENGINE_VERSION` (`registry/engine-version.ts`) is what a plugin's `engineRange` is checked against at install: a plugin whose range the engine version does not satisfy is rejected with `PLUGIN_INCOMPATIBLE`. `PluginRegistry.resolve` and `resolveDependencyOrder` pick, for a dependency that names a range, the highest registered version that satisfies it; a dependency with no range takes the latest registered version.
