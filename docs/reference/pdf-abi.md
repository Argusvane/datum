# PDF ABI

`PDF_ABI_VERSION` (`engine/form-engine/render/pdf/pdf-abi.ts`) is the version of the contract between a host and the portable PDF program (`dist/datum-pdf.program.js` in `packages/pdf-kernel`, shipped in the web components bundle folder as `datum-pdf-program.js`, ADR 0043): the requests a host sends it (`capabilities`, `document`, `build`, `render`, `layout`, `fill`, `inspect`, `sign`, `complete`, `timestampRequest`, `verify`) and the replies that come back. It is versioned apart from the validation program's `WASM_ABI_VERSION` ([Sandbox ABI](sandbox-abi.md)), because the two programs ship and evolve separately. The current value is `4.0.0`. The major number changes when the shape of a message breaks; the minor number changes when the program prints or judges something differently or accepts or returns an optional key.

Where it is read:

- Every request names an `abi`. The program answers a request of its own major (`pdfAbiCompatible`: both plain `major.minor.patch` versions of one major) and refuses any other as `abi_mismatch`.
- The program answers `capabilities` with `abi` (the constant) and `features`, the list `PDF_PROGRAM_FEATURES` in `packages/pdf-kernel/src/program/entry.ts`. A server host refuses at start a program that reports another major, a version below its floor (4.0.0), or lacks a feature it needs.
- The browser's `renderFormPdf` refuses a provider whose `abiVersion` is not of its own major (`PdfKernelError`, code `abi_mismatch`) before it builds anything.
- The conformance suite (`docs/conformance-suite.md`) runs the `OUT` class against a program of this major that lists the `output-safety` feature.

The program is one import-free ES2020 script exposing `globalThis.__datum_pdf(requestJson) → Promise<string>` and `globalThis.__datum_pdf_register(module)` (a plugin module may carry a `pdfRenditions` array). It holds two layers, so a non-JS host never needs the TypeScript engine: the model builder (the schema readers, the rules evaluator and `render/pdf/*`, which turn a form root, a layout, values and a snapshot of resolved data-source options into a `PdfDocument`) and the kernel (layout arithmetic, the PDF writer, AcroForm fill and inspection, tagging). The operations:

- `capabilities`: the program's `abi` and `features`.
- `document`: form, layout and values to bytes; the one non-JS hosts use.
- `build`: form, layout and values to a `PdfDocument`.
- `render`: a `PdfDocument` to bytes.
- `layout`: a page report with no bytes (the designer's page edges).
- `fill`: a template and values to bytes, with a `fields` report per mapped field (`filled`, `cleared`, `missing` or `unsupported`, the last with a message).
- `inspect`: a template to its fields.
- `sign`, `complete`, `timestampRequest` and `verify`: signing, in [PDF rendering](../pdf-rendering.md#signatures).

The QuickJS host that runs the program has two resource profiles: the validation profile of the [Sandbox ABI](sandbox-abi.md) (`VALIDATION_PROFILE`: 250 ms, 32 MiB) and a document profile (`DOCUMENT_PROFILE`: 15 s, 256 MiB). Both keep the stack at 1 MiB, because the single-file WASM build's stack is about that and a larger limit makes every evaluation fail. `call()` drains pending jobs, because the writer's `save()` is a promise.

Plain JSON, stable-stringified (code-unit key order, as the validation ABI); bytes travel as base64, and the host's time and identity come in `env`, so the same request yields the same bytes on every host. A form root, a layout, values and a data-source option snapshot go in; a `PdfDocument` or bytes come out.

## What the contract carries

| Area | What the messages carry | Features | ADR |
| --- | --- | --- | --- |
| Template areas | `areas` on the `fill` request, answers drawn into rectangles on a PDF's pages, with an `areas` report (`filled`, `empty`, `overflow`, `missing`, `unsupported`) on the `fill` and `document` replies. An area may carry `field`, a transparent AcroForm widget created at the area, and its report names the field. | `areas`, `area-fields` | [0057](../adr/0057-template-areas-and-page-imagery.md) |
| Unknown components | `unknownComponents` (`ignore`, `warn`, `fail`) on `document` and `build`, the `component.unknown` warning and the `unknown_component` failure code. | `unknown-components` | [0043](../adr/0043-pdf-rendering-portable-kernel.md) |
| PDF/A | `conformance` on the document model and the `fill` request, `pdfa` on the render options, the level echoed as `pdfa` on the `document`, `render` and `fill` replies and on `inspect` info, and the `conformance` failure code. | `pdfa` | [0059](../adr/0059-pdf-a-conformance.md) |
| Attachments | Uploaded files as associated files: `attachments` on the document model and the `fill` request, a budget policy (`budgetBytes`, `onExceeded`) on the `document` and `build` inputs, the names embedded echoed as `attachments` on the `document`, `render` and `fill` replies (absent when none were asked for), and the `attachment_budget` failure code. `inspect` reads them back: `attachments` on the request (`none`, `digest` or `data`) and on its info, each file with its digest and, when asked, its bytes. | `attachments`, `attachment-data` | [0060](../adr/0060-uploaded-files-as-pdf-attachments.md), [0064](../adr/0064-submissions-service.md) |

A host fails closed: a `verify` that throws, and a signature with `coversDocument: false` and no `laterRevisions`, are a document whose changes could not be judged. A certification is intact only if every signature in its `laterRevisions.reliedOnSignatures` is itself valid as the host checks it. A consumer treats every `verify` field as optional and tells the program's reach by the feature's absence. | `verify-detail` | [0061](../adr/0061-pdf-digital-signatures.md) |
| Theme geometry | `controls`, `choice`, `fields`, `headings`, `table`, `box`, `panel`, `list` and `spacing` on the document model; `hint`, `labelSuffix`, `prefix`, `suffix`, `frame`, `control`, `width` and `marker` on the field blocks; `tag`, `number`, `band` and `rule` on headings; the `list` block; `weight`, `link` and `transform` on runs; `typography` and `colors` on a fill plan. | `theme-controls` | [0098](../adr/0098-pdf-theme-geometry-and-theme-fonts.md) |
| Themes and fonts | A PDF theme is chosen by id from the render call, the layout, the host's default and the PDF theme the form's design-system binding suggests, then `datum-pdf`. A family no font resource covers is drawn in the default pack's sans-serif face (`font.fallback_default`); the standard 14 are the fallback only for a host that sends no default pack. The font need carries the theme id, and a face a host could not load is the `font.faceFailed` warning. | `default-font-fallback` | [0098](../adr/0098-pdf-theme-geometry-and-theme-fonts.md) |

| Layouts chosen by the answers | A layout in `pdf.layouts` may carry `when`, a condition over the request's `values`; a `document` or `build` that names neither `layoutId` nor `layout` prints the first layout whose `when` holds, else `defaultLayoutId`, else the first. `build` answers with `layoutChoice`; the `document` reply names the layout that printed (`layoutId`, `layoutKind`, `layoutChoice`); `document` refuses with the `template` code template bytes sent for a layout a condition chose. | `layout-conditions` | [0044](../adr/0044-several-pdf-layouts-per-form.md) |
