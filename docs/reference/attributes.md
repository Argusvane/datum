# Attribute reference

Generated by `packages/datum/scripts/gen-attribute-reference.mjs` from the elements' `observedAttributes` and `scripts/attribute-metadata.mjs`. Do not edit by hand; `node scripts/gen-attribute-reference.mjs --check` fails when this file is stale. The machine form is `attributes.json`.

Categories: **R** required, **D** sensible default, **O** opt-in, **J** the attribute carries the declarative part and a JS property carries the rest (functions, custom objects).

## Themes

The form is drawn by a binding (the binding property, bindings.register). Builder-shell themes (theme on the builder; datum-dark ships) and PDF themes (pdf-theme; default and datum-plain ship) are named by id: register others with builderThemes.register or pdfThemes.register before the element connects; an unknown id is reported as datum-error.

### `datum-form` events

| Event | When |
|---|---|
| `datum-submit` | An accepted submission; detail carries the answers, and detail.submissionKey the attempt's key, which the page sends beside the document ({ document, submissionKey }) and again unchanged when it retries the delivery. detail.trigger is "agent" when a browser assistant's submit tool started it, and detail.agent (an AgentProvenance) says which answers the assistant's tools wrote last; both are absent where the element's tools were never live: a form that has only ever been sealed adds none. |
| `datum-change` | A settled value change. |
| `datum-validated` | Validation finished. |
| `datum-error` | A problem the page should know of: { code, message, cause? }. The code names the cause (definition.load, definition.too-large, sandbox.unavailable); the message is words to show. An unreadable definition, a sandbox that never loaded. |
| `datum-binding-error` | The binding or its files failed: detail.hook says where (assets: a stylesheet or script of the design system could not be had, with detail.url, and an alert takes the form's place; binding: an id nobody registered; render, ready, focus and self-check: a hook of the binding), detail.message why. Bubbles and is composed. |
| `datum-form-action` | A button was pressed whose action the element does not act on itself; the page hears it and decides. detail is { componentId, action, signature?, journey? }: the button's id, its configured action as written, its signature option. The element handles submit and download buttons, a journey's own Submit, and a pdf button while it can make a PDF (as datum-submit, datum-download and datum-pdf), and stops those; any other action, and a pdf button when no PDF module is set, reaches the page here. |
| `datum-download` | Cancelable; an accepted submission saved as a file. |
| `datum-pdf` | Cancelable; a PDF was made (the PDF button, downloadPdf() or a browser assistant's download_pdf tool); cancelling takes the file over, so the page sends it where it wants. detail.trigger is "agent" for the assistant's tool, and detail.agent is the AgentProvenance account, absent where the element's tools were never live: a form that has only ever been sealed adds none. |
| `datum-print` | Cancelable; print() routed elsewhere if cancelled. |
| `datum-ready` | The form is built and drawn; one microtask after the definition lands for a plain form, one chunk load later for the first journey form on a page. The ready promise settles with it. |
| `datum-page-change` | The journey moved to another page. |
| `datum-locale-applied` | A locale took effect; detail.locale is its code. |
| `datum-locale-rejected` | The person picked a language in the form's own switcher that the form does not declare. detail is { locale, message }: the code picked and the runtime's reason. The switcher has been put back to the form's current language, and nothing else changes. |
| `datum-wasm-ready` | The validation sandbox loaded. |
| `datum-wasm-validated` | The sandbox finished a check. |
| `datum-agent-action` | With the agent feature: a browser assistant's tool call finished. detail names the tool, its outcome and what it changed; see Assistants. |
| `datum-agent-session` | With the agent feature: an assistant's session began, ended, was stopped or went idle; detail.phase says which. |
| `datum-agent-tools` | With the agent feature: the tools were registered, sealed or withdrawn; detail.registered, detail.access and, when not registered, detail.reason say which. |
| `datum-warning` | Something taken, but not whole: detail.code draft.dropped says restoreDraft() left out answers the form cannot hold (an object or a list in a single-valued field), with detail.count and detail.addresses (the first few); the rest is restored. |

### `datum-form-builder` events

| Event | When |
|---|---|
| `datum-builder-change` | The definition changed. |
| `datum-builder-file-action` | A New, Open, Download or Save action was taken. detail.trigger is "agent" when a browser assistant's save tool asked for the Save, so a host's save can tell who asked. |
| `datum-builder-save` | The Save the save attribute turned on was chosen (cancelable). detail.definition is the form to store, detail.localeChanges the languages changed since the last save, detail.trigger "agent" when a browser assistant asked; detail.waitUntil(promise) has the save wait on the page's work and fail with its rejection, and preventDefault() leaves out the request to the address in save. Not fired for a fileActions.save function. |
| `datum-builder-workspace-change` | The workspace changed. |
| `datum-builder-dirty-change` | Unsaved changes began or ended. |
| `datum-builder-mode-change` | The builder mode changed. |
| `datum-builder-binding-change` | The canvas's binding changed: detail.bindingId. |
| `datum-builder-full-window-change` | Full window opened or closed. |
| `datum-builder-scheme-change` | The builder's colour scheme changed once the builder was up, from the Dark mode switch in the ⋮ menu or a change to the scheme attribute: detail.scheme is light or dark. The scheme attribute follows a change made from the menu. Choosing a theme (theme="datum-dark") does not raise it. |
| `datum-agent-action` | With the agent feature: a browser assistant's tool call finished. detail names the tool, its outcome and what it changed; see Assistants. |
| `datum-agent-session` | With the agent feature: an assistant's session began, ended, was stopped or went idle; detail.phase says which. |
| `datum-agent-tools` | With the agent feature: the tools were registered, sealed or withdrawn; detail.registered, detail.access and, when not registered, detail.reason say which. |
| `datum-pdf-layout-change` | A PDF layout was edited. |
| `datum-pdf-layout-select` | A PDF layout was selected. |
| `datum-pdf-designer-ready` | The PDF designer is ready. |
| `datum-journey-change` | A journey was edited. A page or journey given another id reports reason page-rename or journey-rename with renamed ({ journeyId, from, to }); the form's tests follow it by themselves, so a host forwards nothing. |
| `datum-journey-select` | A journey was selected. |
| `datum-error` | A problem the page should know of: { code, message, cause? }, the code naming the cause (definition.invalid, definition.too-large, attribute.origin-refused). A definition refused (unreadable, too large, or arriving while another source is loading), an attribute refused (another origin). |
| `datum-warning` | Something taken, but not whole: detail.code translations.dropped says a loaded form's unusable translation entries were left out, with detail.count and detail.addresses (the first few); Save writes the rest. detail.code src.superseded says a src response arrived after the author edited and was not loaded over the edits. |
