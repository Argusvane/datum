# ADR 0140: The formula builder

## Status

Accepted.

## Context

Rules are stored as formulas (ADR 0139). A structured editor over them, flat rows of field, test and value joined by all or any, is a lossy recogniser over a language the author writes directly: a calculated value, a nested condition and anything with `if` would open as raw JSON, and the condition words had three copies. The builder needs one editor shared by the Logic workspace (ADR 0127), the inspector, and the journey and PDF designers. It is not a bare code box: a field that reads as a sentence, with chips for fields, helpers for the pieces non-technical authors reach for, live problems and a Try it. What the editor offers, as an author sees it, is described in `docs/formulas.md`, "The formula editor in the builder".

A formula problem never disables Apply (ADR 0111).

## Decision

1. **One editor, a sentence rather than code.** `builder/formula/formula-editor.ts` exposes `mountFormulaEditor(parent, options): CodeMirrorFormulaEditor`. The public path is the lazy loader `loadFormulaEditor()` exported from the builder index, whose resolved module carries `mountFormulaEditor` (`mountFormulaTextarea` is exported directly). CodeMirror sits underneath (decorations, widgets, lint, autocomplete, undo) but nothing says so: no gutter, no line numbers, no monospace block. A field reference draws as the rule sentences' label chip (an atomic range that Backspace removes whole); an unknown field's mark is not atomic, so a misspelt field can be corrected one letter at a time. A value rule is multiline, a condition is one line and Enter commits. The StreamLanguage tokenizer is the editor's own (`scanFormula`); the parse is the engine's `kernelParseFormula`. The styles are `FORMULA_EDITOR_STYLES`, appended to each host's shadow sheet with three-class selectors so they beat CodeMirror's adopted base sheet, and they read the builder's `--db-*` tokens.

2. **Chips store ids.** The stored text is always ids (`feelName(id)` backticks an id the grammar cannot take bare or a keyword); labels are a reading.
   - `printFormula(expression, { labelOf?, optionLabelOf?, multiline? })` (`feel-print.ts`) prints a tree in canonical spelling and is lossless by structure: `parse(print(tree))` deep-equals the tree for every tree.
   - A tree-stored rule opens printed with ids; with `labelOf` the output is for reading only, never reparsed.
   - `printFormulaTokens` gives the token form for "Reads as".

3. **Helpers, snippets and suggestions** come from one table. The function rows are `formulaFunctionRows(registry)` (`feel-functions.ts`): built-ins merged with `FORMULA_FUNCTION_DOCS`, then the wired plugins' declarations, so a plugin's function is a first-class helper. The snippets are `FORMULA_SNIPPETS`, data in the same file, with a wired plugin's `snippets` joining them. The fields offered are `formulaFieldsOf(root)`. A helper inserts at the caret with each blank selected in turn and Tab moving through them (CodeMirror's `snippet()`), and a helper button or menu press keeps the box's focus. The "Formula reference" link (`referenceHref`) is drawn only when the host sets it: the builder has no documentation page of its own, and a default address would be a dead link in an application that embeds it. The Variables panel's intro and the inspector's editors follow the same rule, with no empty anchor and no spacer left behind.

4. **Lint, Reads as, Runs.** Problems come from one place, `formulaEditorState(text, { fields, signatures, scopes, locale, catalog })` (`formula-textarea.ts`), so the editor and the fallback say the same thing. An unknown field is a `paths` span naming nothing the form stores (scoped paths skipped); marks are set in a microtask after each change. Error codes are worded from the builder catalog (`formula.err.<code>`; `formulaErrorText` and `formulaProblemText` also word `runScope` and `invalidRule`). "Reads as" is the rule-list sentence (`conditionSentence`) for the shapes it already words, else the printed formula. "Runs" sits in the editor head for the keys that may take a scope; `defaultValue`, `filter` and `navigationGating` show a fixed Browser chip, a journey or PDF `when` shows none, and the rule list says a browser-printed PDF leaves a secret field blank.

5. **Try it, per side.** As ADR 0127 describes, plus the computed value for a value rule, a date box when the formula reads the clock (`BuilderPreviewRuntimeOptions.today`, passed to the orchestrator), and the side wording. A server-only rule is still evaluated in the preview (the tree is spliced whatever the scope), so the author sees what the server will decide. The preview runtime takes the plugin functions, so Try it evaluates them.

6. **The Logic workspace** (`logic-surface.ts`, `logic-model.ts`, `logic-types.ts`) uses the editor as its only rule editor; ADR 0127 describes the surface. Apply writes the text as a bare string, or `{ formula, run }` when the scope is not `both`, and a rule key is written only when its text or run changed or the rule is new, so a tree rule stays a tree when only the hidden-answer choice changed. Every word the surface draws is a `builder-texts.ts` key read in the surface's locale and catalog. The editor's `onCommit` refreshes the live parts exactly as `onChange` does and never repaints: a repaint under Apply's mousedown would swallow the click. Structural changes (target, run, kind) repaint, with the box's DOM moved into the fresh slot, never rebuilt.

7. **The inspector's Logic tab** (`builder-shared.ts` `rulesTabHtml`, `builder-panels.ts`, `rules-model.ts`) shows per rule an Off / Formula pill (`RuleEditorMode = "off" | "formula"`) and the compact box, with the problem line under it (`aria-describedby`, `aria-invalid`). A journey route's `when` and a PDF layout's `when` get the same editor through their target descriptors (`journey-builder-mode.ts`, `pdf-builder-mode.ts`, `layout-conditions.ts`), with `BuilderModeRules.formulaFields(nodeId)` supplying the fields a mode offers and `scopes: []` for a mode's rules. `composeRuleSource(existing, text, run)` keeps a stored tree when the text still prints it (bare for `both`, `{ expression, run }` otherwise), else writes the string or `{ formula, run }`. `buildRuleEditorState` opens a string as written, the object form with its `run`, a tree printed (JSON when the printer cannot word it). The JSON view accepts all three shapes (`isRuleSourceShape`, `knownFunctions` for the wired plugins). A hand-typed call to a function the table and the wired plugins do not know is refused when it is applied, as `unknownFunction`.

8. **The paint contract: live draft changes.** Every keystroke whose text parses writes the draft as typed (`setDraftRules` / `setDraftProperty` with `{ live: true }`; `BuilderChangeEvent.live`). The panel that wrote it refreshes in place (`refreshRuleLive`: the feedback block, the box's aria state, the footer summary), the canvas returns without a paint, and everyone else sees an ordinary `edit`. The commit (`onCommit`, focusout, a Try-one chip) writes the same draft plainly once so the canvas catches up with one change.

   Text that does not parse writes nothing to the draft in Logic. In the inspector it is written as typed and held: the controller's `problemsOf` lists `rules:<key>` for a draft rule whose text does not parse (`ruleProblemsFor`, built-in signatures; `unknownFunction` alone is the panel's, since only it knows the host's plugins) and `commitDraft` refuses it, so Apply, the leave guard and any direct caller see it. The summary line above Apply repeats the message and clicking it focuses the box (ADR 0111).

   `BuilderControllerOptions.ruleTargets` names the property paths that hold formulas (the PDF mode registers `["when"]` on each layout controller), so `problemsOf` and `commitDraft` hold them as `rules:<path>`. A rule stored unparseable by someone else is never a problem that holds Apply back. The editor is lifted across the structural repaints that remain, as the JSON viewer is.

9. **The rename seam.** `renamePathsInFormula(text, from, to, signatures?)` (`formula/rename.ts`) rewrites the parser's `paths` spans and keeps the author's formatting. `renameInRuleSource` handles a string, a tree and the object form and returns the same reference when nothing changed; a formula that does not parse but spells the old id is left as written and reported (`unparsedFormulaNaming`).
   - `BuilderController.renameId` rewrites every rule of every component that reads the old id, in the tree and the open drafts, as one recorded history step (`RENAME_RULES`). `BuilderChangeEvent.renamed` is `BuilderRename { from, to, rules?, unparsed? }`, and `renameFollowsRules: false` leaves the rules to a tree's owner (the journey designer renames its own nodes itself).
   - `journey-references.ts` and `layout-conditions.ts` rename route `when`, worked-out values, and a template layout's field and area expression sources (returning `unparsed`), all through the same seam. An open PDF template designer follows a form rename (`followRenameInTemplateTree`), and unparsed sources are reported on the layout's status line. A layout's `component` and `path` bindings follow the same rename in the PDF mode (ADR 0044 decision 17).

10. **There is no flat condition model.** Rules are text. The condition words live once, in `condition-words.ts` (`conditionTerms`, `conditionInWords`), which the journey components and the flow map read; what does not fit a sentence is the printed formula instead of "a custom condition".

11. **Form settings and the Variables panel.** The Form settings panel has a "Formulas" section with `formulaErrors` as Fail (the default) and Warn (`formula-settings.ts`, stored at `root.configuration.formulaErrors`; picking the default over a form that sets nothing writes nothing; a stored word it does not know shows as Fail, ADR 0139 decision 6). The Variables panel derives its functions from the same table and its field rows copy `feelName(id)`.

12. **Hosts, the fallback and the chunks.** `<datum-builder>` takes `formulaFunctions` (anything with `table()` and `signatures()`; the plugin platform's `FormulaFunctionRegistry` fits), `formulaReferenceHref`, `textLocale` and `textCatalog`, and hands them to the Logic surface, the inspector, the Form settings panel and the Variables panel. `<datum-form-builder>` builds a registry from its wired plugins' `formulaFunctions` when none is set.

    Every host mounts `mountFormulaTextarea` first (eager, fully functional: parses on change, problems under it) and swaps in `mountFormulaEditor` when `loadFormulaEditor()` resolves, carrying text and caret across. A rejected load is forgotten (so a retry can succeed), and the textarea stays with a "failed, retry" line. The editor is a lazy chunk beside the shared CodeMirror chunk the JSON viewer loads; `@codemirror/autocomplete` and `@codemirror/lint` are engine dependencies. The Logic model is a lazy chunk of its own that the inspector asks for on the first rule drawn, re-wording Reads as in place when it lands. check-bundles requires the editor's `f-field unknown` mark class to appear in no eager bundle and in one lazy chunk.

## Reasoning

- **One editor, built as a sentence.** A non-technical author loses dropdown discovery and gains helpers, suggestions, live problems and sentences for the simple shapes. The alternative, keeping row editors beside a formula box, leaves two models of a condition that disagree about what they can express.
- **Ids stored, labels shown.** A rename of a field must not change what a rule means, and a label can be reworded or translated.
- **Lossless printing.** Because `parse(print(tree))` is the tree, a rule stored as a tree can be opened as text and written back without changing meaning, and untouched rules are never rewritten.

## Consequences

- One editor for the Logic workspace, the inspector, the journey designer and the PDF designer; one place that words a problem; one place that renames a path.
- Keystrokes do not paint the inspector or the canvas; a controller change may be `live`.
- A tree-stored rule opens printed as a formula and is written back as text only when edited. A `visibleWhen` whose top node is `not` over a non-path lists as "Hide X when …". Anything a sentence cannot word lists as the printed formula.
