Datum web components

Pages that load the built bundles from dist/ the way any host page would. Run npm run build first, then npm run demo.

  • Form renderer — <datum-form> via <script type="module">
  • Form renderer, classic script — the same through datum-form.iife.js and window.DatumForm
  • A journey — the form a page at a time: a branch, an exit page, and checks with the service on a page and before the answers are sent, answered by a stand-in you switch with ?check=ok|slow|invalid|down
  • Presentations — one form filled through a journey with fields of its own (an alias, a value worked out from three months) and a one-page journey that looks like the form, what is submitted beside what stays in the browser
  • Validate in the sandbox — <datum-form wasm="auto"> fetching datum-wasm.js, with rules of the page's own run at submit inside QuickJS
  • Form builder, contained — <datum-form-builder layout="contained"> inside a page that has other content
  • Form builder, full page — the default window-pinned layout under a host header
  • PDF layout designer — <datum-form-builder workspaces="pdf" layout="contained" pdf="auto"> over the intake form, with a real PDF preview
